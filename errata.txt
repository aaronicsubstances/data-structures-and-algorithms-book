Chapter 12: There is a clarification omitted in the code for 
"Adding a key to a Randomized BST" and "Splitting the BST", where
the newNode call in add() which takes left and right arguments (labelled with a "4"),
uses right of _split's return for the left and the left of _split's return for
the right. Although correct, I think it deserves a clarification at least.
Better still, I think the newNode call should simply take the left and right of 
_split's return value. And then the _split function should be modified
to pass the fields of newTrees and lastNodes parameters as
separate parameters in place of newTrees and lastNodes, so that there
is 4 instead of 2 parameters. Then when the tree becomes empty in the step
labelled "1", a new object should be constructed and returned with the
expected left and right fields.

The chapter's use of "side" and "other" in code sections for "left" and "right"
helps to avoid if else,
but I think it sacrifices brevity for clarity. Many times I had to 
decompress the code to use "left" and "right", before I understood what
the code section.
